# SOCIETAL INNOVATION COLLABORATION PORTAL
## Complete Development Plan — Stack: PostgreSQL + FastAPI + React.js

================================================================================
## 1. PROJECT OVERVIEW
================================================================================

A platform connecting four actor types:
1. CITIZEN (Problem Uploader) — individuals, community groups, PRIs, ULBs, govt depts
2. UNIVERSITY (HEI - Higher Educational Institution) — students + faculty mentors
3. INDUSTRY / STARTUP / COMPANY — mentoring, co-development, funding, prototyping
4. GOVERNMENT — oversight dashboard, analytics, monitoring

Core loop:
Citizen submits problem (+evidence: photo/video/voice/text/location)
  -> AI validation, categorization, priority scoring, duplicate detection
  -> Routed/nudged to registered solvers (tag-matched, except HEIs who see all)
  -> University team + faculty mentor forms, produces solution proposal
  -> Proposal posted back on portal -> Industry/Startup can pick it up
  -> Collaboration -> Prototype -> Pilot -> Implementation -> Social Impact
  -> Government dashboard tracks everything end-to-end

================================================================================
## 2. ACTORS, ROLES & PERMISSIONS
================================================================================

| Role            | Can Do                                                                 |
|-----------------|-------------------------------------------------------------------------|
| Citizen         | Register/login, submit problem w/ evidence (text/image/video/voice/geo), track status, view public problems on map, comment/upvote |
| University Admin| Register institute, manage student/mentor accounts                     |
| Student         | Join project team, view ALL problems (no domain tag restriction), submit solution proposal, update proposal status |
| Faculty Mentor  | Approve/guide team, co-sign proposal, manage milestones                |
| Industry/Startup| Register with optional domain tags, receive tag-matched problems + posted solutions, express interest, fund/co-develop, update prototype/pilot status |
| Government      | View analytics dashboard, district/sector-wise stats, approve/monitor, no direct problem submission |
| System/AI Agent | Auto-categorize, tag, detect duplicates, transcribe voice->text, prioritize, route |

Tag rule:
- Industry/Startup: tags are OPTIONAL (if none, they see all problems too — configurable)
- University/HEI: NO tags at all — they always receive/see every problem so students can explore freely

================================================================================
## 3. HIGH-LEVEL SYSTEM FLOW (matches your ASCII diagram)
================================================================================

Citizen
  -> Submit Problem (text/image/video/voice + geolocation)
  -> Societal Innovation Portal (API ingestion)
  -> Problem Validation (spam/completeness check)
  -> AI Categorization + Priority Scoring + Duplicate Check (LLM API call)
  -> Routing Engine: tag match -> University Matching (all HEIs) + Industry Matching (tag-based)
  -> University Team + Faculty Mentor formed
  -> Solution Proposal drafted & submitted
  -> Industry/Startup Partner reviews proposals feed
  -> Collaboration -> Prototype -> Pilot Test -> Implementation -> Social Impact logged
  -> Government Dashboard aggregates every stage in real time

Key relationships:
- USERS 1--N PROBLEMS (as citizen)
- PROBLEMS 1--N EVIDENCE
- PROBLEMS N--N TAGS (via PROBLEM_TAGS)
- PROBLEMS 1--N TEAMS (a problem can have multiple competing university teams)
- TEAMS 1--1..N PROPOSALS
- PROPOSALS 1--N COLLABORATIONS (one proposal, potentially multiple industry partners, or 1:1 if exclusive)
- COLLABORATIONS 1--N MILESTONES 1--N DELIVERABLES
- COLLABORATIONS 1--0..1 SOCIAL_IMPACT_REPORTS
- INDUSTRIES N--N TAGS (via INDUSTRY_TAGS) — optional
- UNIVERSITIES have NO tag relationship table (by design, per requirement)

## 8. AI / LLM INTEGRATION POINTS
================================================================================

1. Voice-to-Text: send audio evidence to an LLM/STT API (e.g., Whisper API or
   Gemini audio understanding) -> store transcript in EVIDENCE.transcript
2. Categorization + Tagging: send problem title+description+transcript to LLM
   with taxonomy.json as context -> return top-N tags + confidence scores
3. Priority Scoring: LLM prompt scoring urgency/impact/scope (1-10) using
   rubric (public safety > infra > convenience) -> PROBLEMS.priority_score
4. Duplicate Detection: generate embeddings (via LLM embeddings API) for each
   new problem, vector-similarity search (pgvector extension in Postgres)
   against existing OPEN problems in same district -> flag if similarity > threshold
5. Routing Engine (rule-based, not LLM): 
   - ALL problems -> ALL universities (no filter)
   - Problem tags intersect Industry tags (or industry has no tags set) -> notify industry
6. Proposal Summarization (optional): LLM generates short public-facing summary
   of long proposal for citizen/government view

Recommended: keep AI calls in services/ai_categorization.py etc. as thin wrappers
so the underlying LLM provider is swappable via config.py (model name in .env).

- Backend: store lat/lng directly on PROBLEMS and INDUSTRIES tables;
  proximity queries via PostGIS (ST_DWithin) or Haversine formula in SQL
  for "problems near me" on industry dashboard
